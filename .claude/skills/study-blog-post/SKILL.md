# 학습 노트 → 블로그 글

## 역할 분담

| 단계 | 하는 사람 | 산출물 |
|---|---|---|
| 1 개요 | AI | 제목 후보, 목차, 절마다 "무엇을 서술하라", 쓸 코드, 제외 소재 |
| 2 집필 | 사용자 | 본문 산문 |
| 3 검토 | AI | 사실 오류 지적, 문장·맞춤법 다듬기 |

**AI는 본문 산문을 쓰지 않는다.** 1단계 산출물은 지침과 코드까지다. 문단을 완성해서 주면 위반이다.

경계가 애매한 지시가 오면 개요 범위인지 되묻는다. 2026-08-23에 "나머지는 너가 알아서 채워줘"를 본문 집필 위임으로 읽고 11,600자를 대신 써버린 전례가 있다. 아래 표현은 모두 개요 범위로 읽고, 본문까지 원하면 사용자가 그렇게 말할 때만 쓴다.

- "나머지는 알아서" · "정리해줘" · "채워줘" · "제목은 N번으로"

## Phase 1 — 개요

### 읽을 것

1. **학습 노트** — 해당 주제 디렉터리의 `README.md`(확립된 사실 · 사다리 · 진행 규칙)와 `journal.md`(세션 로그 · 오개념 표 · 복습 큐). 글감은 여기서만 나온다.
2. **이번 글의 범위** — 어느 회차에서 배운 것을 쓸지 확정한다. 노트의 세션 로그와 단원 상태로 잘라내고, 애매하면 사용자에게 묻는다. 범위 밖 소재는 개요에 넣지 않는다.
3. **직전 글** — 이미 발행한 앞 편. **읽는 목적은 인용이 아니라 배제다.** 거기서 다룬 소재를 이번 글에 끌어오지 않기 위해 확인한다.
4. **글 놓을 자리** — Notion 페이지 URL 등. Phase 3에서 다시 읽어야 하니 개요와 함께 기록해 둔다.

### 글은 단독으로 성립한다

**앞 편 내용을 끌어오지 않는다.** 앞 편을 안 읽은 사람이 이 글만 읽어도 막히지 않아야 한다.

- "지난 글에서는 ~를 다뤘다" 같은 도입을 쓰지 않는다
- 앞 편에서 세운 규칙을 회수 지점으로 잡지 않는다
- 앞 편 소재를 요약해 넣지 않는다. 요약도 재설명이다
- 이번 글의 논증에 앞 편 개념이 필요하면 앞 편을 가리키지 말고 **그 자리에서 필요한 만큼만 사실로 진술한다**

시리즈 연결은 발행 플랫폼이 한다. 본문에서 할 일이 아니다.

### 스파인 하나를 정한다

이번 회차 소재를 그냥 이어 붙이면 나열이 된다. 독자가 따라올 축을 하나 세우고 소재를 그 축에 배치한다. 축이 안 서면 두 편으로 쪼갤 것을 제안한다.

축 후보를 고를 때 쓸 만한 형태:

- 능력 순서 — 읽기 → 만들기 → 변환하기
- 목표 하나 — 표준 유틸리티를 직접 만들면서 필요한 도구를 순서대로 꺼낸다
- 막히는 지점 하나 — 안 되는 것을 보여주고 그것을 풀어 가며 문법을 꺼낸다

### 하나의 글로 읽히게 배치한다

주제별 목차를 나열하면 사전이 된다. 글은 이어져야 한다.

- **소제목에 번호를 붙이지 않는다.** `1.` `2.`가 붙으면 독립된 항목의 목록으로 읽힌다
- **소제목은 내용을 말하는 문장으로 쓴다.** `as 절` 대신 `as 절이 키 자리를 연다`
- **절 개수를 줄인다.** 소재가 많으면 절을 늘리지 말고 한 절 안에서 이어 쓴다. 소제목 없이 문단으로 넘어가도 된다
- **절마다 연결 문장으로 시작한다.** 앞 절이 남긴 물음이나 한계를 이어받는 한 문장. 개요에 그 문장의 내용을 지정한다
- **회수 지점은 같은 글 안에서만 잡는다.** 앞 절에서 세운 것이 뒤 절에서 다시 쓰이는 자리를 표시한다

### 개요 산출물

절마다 아래를 정한다. 산문은 쓰지 않는다.

| 항목 | 내용 |
|---|---|
| 이어받을 것 | 앞 절이 남긴 물음·한계. 절 첫 문장이 여기서 나온다 |
| 서술할 것 | 이 절에서 세울 주장. 문단이 아니라 지시문 |
| 쓸 코드 | 노트에서 검증된 코드 블록 그대로 |
| 회수 지점 | 같은 글 앞 절에서 세운 규칙 중 여기서 다시 쓰이는 것 |
| 강조할 한 문장 | 절의 결론. 사용자가 자기 문장으로 풀어 쓸 재료 |

**이 표는 AI가 무엇을 정해야 하는지의 목록이고, 페이지에 그대로 옮기는 서식이 아니다.** 정한 것을 항목 라벨 없이 한두 줄 지침으로 합쳐 쓴다.

### 페이지에 넣는 것과 넣지 않는 것

페이지에 들어가는 것은 셋뿐이다.

1. 소제목
2. 그 절에 무엇을 서술할지 — 항목 라벨 없이 한두 줄
3. 코드 블록 — **결과는 비운 상태로**

**진행 메모를 페이지에 쓰지 않는다.** 아래는 전부 대화로 전달하고 페이지에는 남기지 않는다.

- 글의 축·스파인 설명
- 이번 글의 범위, 넣지 말 것 목록, 앞 편 소재 배제
- 용어 주의, 렌더링 주의 같은 도구 사정
- 분량 지시, 절 나누기·소제목 금지 같은 형식 지시
- 코드가 어떻게 검증됐다는 설명

이유는 같다. 그것들은 **개요를 만드는 사람의 판단 근거**이고 글 쓰는 사람이 읽을 내용이 아니다. 페이지에 쌓이면 지워야 할 것이 늘고, 지침이 본문보다 길어진다.

지침은 사용자가 본문을 채우면서 지운다. 지울 것이 적어야 한다.

### 정답을 적지 않는다

**개요는 문제지다.** 채우면서 쓰는 것이 복습이고, 답이 적혀 있으면 베끼기가 된다.

비우는 것:

- 코드 블록의 결과 주석 — `// 'shape'` 대신 `// ?`
- 추적 주석의 각 단계 결과
- 에러가 나는 예제 — 무슨 에러인지 쓰지 말고 "에러가 나나, 나면 무엇" 형태로
- 결론을 담은 요약 표 — 헤더만 남기고 셀을 비운다
- 규칙을 그림으로 정리한 도식 — 자리·번호는 남기고 설명을 비운다

그대로 두는 것:

- 타입 정의(`type Circle = { ... }`)와 평가할 표현식
- 문법 골격(`{ [K in keyof T as ?]: ? }`처럼 채울 자리를 표시한 형태)
- 절 소제목

**지침도 결론을 말하지 않는다.** "`keyof`는 교집합이다"가 아니라 "두 결과가 어떻게 갈리는지 채운 뒤 방향을 한 문장으로 정리한다"로 쓴다. 무엇을 쓸지 지시하고, 무엇이 답인지는 말하지 않는다.

검증된 값은 AI가 들고 있다. 사용자가 막혀서 확인을 요청하면 그때 준다. 요청 없이 먼저 알려주지 않는다.

## Phase 2 — 사용자 집필

AI는 기다린다. 사용자가 일부만 쓰고 물어보면 그 절 범위에서만 답한다. "이 문단 어떻게 시작할까"에 문단을 써주지 않는다 — 재료(코드·주장·회수 지점)를 다시 제시한다.

## Phase 3 — 검토

사용자가 채운 글을 받으면 아래 순서로 본다. **채운 값과 사실 검증이 먼저다.** 문장 다듬기부터 시작하면 틀린 내용이 매끄러워질 뿐이다.

### 0) 채운 값 대조

개요에서 `// ?`로 비워 둔 자리를 사용자가 채웠다. **그 값부터 실측과 대조한다.** 이것이 복습의 채점이다.

틀린 값은 값만 고치고 넘어가지 않는다. 왜 그 값이 나오는지, 어디서 갈렸는지를 짚어야 다음에 안 틀린다. 오개념으로 보이면 학습 노트의 오개념 표에 올릴 것을 제안한다.

### 1) 사실 오류

채운 값 밖의 것 — 산문에 쓴 규칙·설명·용어를 검증한다. 근거는 실측이다.

```
npx -y -p typescript@5 tsc --strict --noEmit --target es2022 <file>
```

`Eq`/`Assert` 이디엄으로 값을 고정한다.

```ts
type Eq<X, Y> = (<T>() => T extends X ? 1 : 2) extends (<T>() => T extends Y ? 1 : 2) ? true : false;
type Assert<T extends true> = T;
```

에러 메시지를 인용하는 문장은 실제 컴파일러 출력과 대조한다. 기억으로 쓰지 않는다.

찾은 오류는 이렇게 보고한다. 고쳐 쓴 문장을 바로 들이밀지 않고 무엇이 틀렸는지부터 말한다.

- 원문 인용
- 무엇이 틀렸나
- 실측 출력
- 어떻게 고칠지 제안

**과잉일반화가 가장 흔한 오류 부류다.** 조건이 붙어야 하는 규칙을 무조건으로 쓴 문장. 규칙을 볼 때마다 "예외가 있나"를 실측으로 확인한다.

### 2) 용어

핸드북·공식 문서에 없는 용어를 쓰고 있으면 알린다. 출처가 컴파일러 소스나 오래된 PR뿐인 용어는 각주를 붙이거나 풀어 쓰기를 제안한다. 이미 확인한 것은 노트의 "용어 출처" 절에 있다.

### 3) 문장·맞춤법

여기까지 오면 직접 다듬는다. 허용 범위는 문장 단위다.

- 맞춤법·띄어쓰기·조사
- 문장 분리·병합, 어순
- 중복 표현 제거

**내용을 더하거나 빼지 않는다.** 문단을 새로 쓰거나 주장을 추가하는 것은 제안으로만 낸다. 사용자가 쓴 목소리를 유지한다.

코드 블록·에러 메시지·타입 이름·표의 셀 값은 한 글자도 바꾸지 않는다. 다듬은 뒤 코드 블록이 바이트 동일한지 확인한다.

`humanize-korean` 같은 AI 티 제거 도구는 **기본으로 돌리지 않는다.** 사람이 쓴 글이다. 사용자가 명시적으로 요청할 때만 쓴다.

### 검토가 끝난 절은 지침을 지운다

한 절의 검토가 끝나면 **그 절의 지침 블록을 AI가 지운다.** 사용자가 지우게 두지 않는다.

이러면 페이지에 남은 지침이 아직 안 쓴 절의 것뿐이 되어 페이지 자체가 진행 표시가 된다. 어디까지 왔는지 물어볼 일도, 다 쓴 뒤 지침을 훑어 지울 일도 없어진다.

지침에 있던 요구를 사용자가 빼기로 했으면 **되살리지 않는다.** 뒤 절에서 자연히 다뤄질 내용이면 거기서 나온다. 검토 보고에 "이 지침이 아직 안 채워졌다"를 다시 올리지 않는다.

## 발행

`publish` 같은 발행 플래그는 AI가 켜지 않는다. 검토가 끝났다고 알리고 발행은 사용자에게 맡긴다.

## 공통 규칙

- 값은 제시 전에 실측한다. 검증 없이 "아마 이렇게 된다"를 쓰지 않는다.
- 코드 블록은 원본 축자다. 변형·값 대입 금지.
- 개요·검토 결과에서 과거 사실을 번호(`3절의 X2`, `Unit 1 사실 목록`)로 참조하지 않는다. 인용할 사실은 그 자리에 코드 한두 줄로 다시 쓴다. 터미널 대화에는 되돌아볼 목차가 없다.
- 글 본문에서도 절을 번호로 가리키지 않는다. 소제목에 번호가 없으니 가리킬 번호도 없다. 앞에서 세운 것을 다시 부를 때는 그 내용으로 부른다.
- 1인칭 오답 서사를 쓰지 않는다. 학습 중 틀린 것을 글의 소재로 삼지 않는다. 개념 정리가 목적이다.
